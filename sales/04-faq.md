# agentlens-audit 常见问题与异议处理

---

## 1. 和 LangSmith / Langfuse 有什么区别？

LangSmith 和 Langfuse 是「观测平台」，帮你看到 Agent 在做什么——追踪调用链、记录耗时、展示 token 用量。agentlens-audit 是「审计工具」，告诉你 Agent 做得对不对——有没有越权、有没有浪费、有没有合规风险。打个比方：观测平台是行车记录仪，agentlens-audit 是交警的责任认定书。两者不冲突，可以配合使用：观测平台负责日常监控，agentlens-audit 负责定期审计 + CI 门禁。

---

## 2. 我们公司没有合规压力，还需要这个吗？

即使没有监管压力，有两个实打实的好处：第一，成本——实测可避免成本浪费 63-76%，重复调用、大输出注入这些浪费如果不审计，基本发现不了。第二，出事了能追责——Agent 系统出 bug 是迟早的事，有了完整的证据链和决策审计，排查问题从「翻几天日志」变成「打开报告看一眼」。合规不是唯一动机，效率和安全也是。

---

## 3. 审计会不会很慢？能处理多少事件？

我们的验证数据：完整审计 11268 个事件，产出 727 个 findings，全部验真通过。因为 agentlens-audit 是纯 Python stdlib 实现（零第三方运行依赖），没有额外的网络调用或数据库依赖，审计速度取决于事件流大小和审计层开启数量。对于日常使用，生产环境每日 03:00 自动审计已稳定运行，说明常规规模下完全可行。

---

## 4. 数据安全怎么保证？审计数据会上传到云端吗？

不会。agentlens-audit 是本地运行的工具——你的事件流文件在本地处理，审计报告生成本地文件。没有云端上传，没有遥测，没有数据外传。对于企业版私有化部署，Web 平台也可以部署在企业内网，不依赖外部服务。自包含 HTML 报告无外链资源，可以离线打开、归档，不用担心报告泄露数据。

---

## 5. 部署复杂吗？需要什么环境？

一条命令安装：`pip install agentlens-audit`。Python ≥ 3.9 即可，零第三方运行依赖，装完就能跑。不需要数据库、不需要消息队列、不需要 Docker（除非你自己想容器化）。Web 平台基于 FastAPI，启动也只需一条命令。跨平台支持 Linux / macOS / Windows。

---

## 6. 支持哪些 Agent 框架？我们用的是自研框架怎么办？

当前支持的输入格式：统一事件流 JSONL、Hermes gateway.log、CrewAI、AutoGen、LangGraph。如果你用的是自研框架，只要能把 Agent 运行事件导出为统一事件流 JSONL 格式，就能接入。框架不绑定是我们的核心设计原则——agentlens-audit 不关心你的 Agent 是哪个框架跑的，只关心发生了什么。

## 8. 审计报告能直接用吗？还是需要二次开发？

开箱即用。审计报告是自包含的 HTML 文件，无外链资源，可以直接在浏览器打开、打印、归档。如果需要结构化数据，`--json` 输出可以接入你的内部系统、BI 工具或自建仪表盘。CI 门禁模式（`--gate`）直接返回非零退出码，可以直接接入 CI/CD 流水线，不需要额外开发。

---

## 9. 修复了问题怎么验证？会不会假修复？

agentlens-audit 有专门的修复回归验证机制：mark-fixed 标记后，需要连续 3 次审计都不再出现该 finding，才会标记为 verified。如果中间复发，直接标记为 regressed。这意味着你修了一个问题，系统会「盯着它看 3 次」，确认真的修好了才算数。这比人工抽查靠谱得多。

## 11. 和公司现有的安全审计工具（如 SonarQube、SAST）区别在哪？

SonarQube 和 SAST 审的是代码——代码有没有漏洞、有没有坏味道。agentlens-audit 审的是 Agent 行为——Agent 运行时的决策、协作、工具调用是不是合规。两者的审计对象不同：一个是静态代码，一个是动态行为。如果你已经在用 SAST 审代码，加上 agentlens-audit 审行为，安全覆盖更完整。

---

## 12. 能定制合规规则吗？我们公司有自己的合规要求。

可以。Annotations 人工合规标注功能允许你对未映射或需要纠正的 finding 进行人工标注，人工判定优先于静态映射表。企业版还支持合规条款定制映射——在你现有的法规库基础上扩展 regulations 映射表，让审计发现自动关联到你公司的内部合规条款。社区版和团队版也可以自己扩展 JSONL 事件流里的自定义字段来适配。如果有特殊需求，企业版支持优先功能请求排期。
